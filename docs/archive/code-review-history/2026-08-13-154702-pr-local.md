# Standard MMRM Profile v1 与轻量案例晋升框架

本次改动把标准分析收敛到 typed YAML contract、共享 `mmrm` engine、SHA-pinned adapter、analysis-scoped artifacts 和十列全局 manifest，并新增仅聚合元数据的案例摘要骨架。非 FCN synthetic fixture 覆盖了真实拟合、collector、tamper rejection 和 legacy contract omission，没有把 FCN study-specific 规则带入共享 engine。但 typed contract 没有完整承载 treatment comparison 的批准语义，案例 registry/promotion 也没有执行文档声明的证据与隐私门，仍可能产出统计上错误但技术上 `complete` 的结果，或接受证据不足的晋升记录。Watch for: **confirmed** treatment reference/direction/adjustment 被 runtime 默认值替代；**confirmed** promotion/evidence 字段只做形状校验；**confirmed** `eq`/`ne` 多值在 R 与 SAS 中产生不同筛选；**confirmed** SAS template 可直接执行但仍自报未执行。

**Verdict**: NEEDS_CHANGES

## High-level view

Contract hash、linked-source hash、adapter hash 和 model identity 构成了 fail-closed 链路，但 treatment estimand 被压缩成三个布尔值。上游要求明确的 reference、contrast direction、CI/multiplicity 没有进入 runtime，R 和 SAS 各自使用默认顺序与比较行为。

`eq`/`ne` 允许向量值，导致 R recycling 与 SAS 首元素筛选不一致；group ID 也没有路径安全化后的唯一性约束，可让两个 group 写入同一个 model RDS。

案例生成器默认输出 `candidate/not_promoted`，但 validator 不约束 registry、promotion 和 evidence 的值，也不阻止自由文本携带 subject 标识。所谓 2–3 个独立 study、人工批准和回归通过目前只是描述文本，不是 gate。

Generator 在 adapter 验证前已经覆盖部分生成文件，并会在 approved adapter 缺失时创建 no-op 文件。SAS template 的未执行状态只是注释，非 adapter/RDS 分支包含可直接运行的 `PROC MIXED`。

Collector 不实现文档声明的 specification-level `fail_fast`，全量失败仍以进程成功结束；engine 又把 contract/adapter、环境和模型失败压进 `blocked_data`/`fit_failed` 两类。Legacy no-contract spec 路径仍保留，但 root validator 可跳过 FCN fixture后仍宣称兼容性已验证。

<details><summary>Details</summary>

## Treatment estimand defaults bypass the approved specification

**Confirmed, high severity.** Statistician input要求 `treatment_reference` 和每个 estimand 的 `contrast`/`direction`（`assets/study-control/statistician-analysis-input-template.md:123,141-144`），`SKILL.md:69` 也要求 reference/direction 明确。Standard contract 只保留 `treatment_visit_lsmeans` 和 `pairwise_differences` 布尔值（`R/standard_contract.R:150-164`）；runtime 使用无批准 levels 的 `factor(data$treatment)` 和无显式 comparison/adjustment 的 `emmeans::contrast(..., method="pairwise")`（`R/standard_engine.R:152-153,248-256`），SAS 则生成裸 `lsmeans _treatment*_visit / cl diff`（`R/standard_sas.R:98-100`）。

已批准的 contract 因而仍可让输出符号、reference ordering 和 multiplicity 来自数据/package 默认值。应在 v1 typed schema 中加入 treatment levels/reference、显式 contrasts、direction、CI level 和 adjustment，并让 R/SAS 共用；若 v1 不支持，则 gate 必须拒绝而不是降级为布尔开关。测试需使用非字母顺序的 reference arm 验证方向。

## Predicate values can select different populations in R and SAS

**Confirmed, high severity.** `standard_validate_predicate()` 没有要求 `eq`/`ne` value 为 scalar（`R/standard_contract.R:44-55`）。R 的 `x == predicate$value` 会按行 recycling（`R/standard_engine.R:58-62`），SAS renderer 则只取 `value[[1]]`（`R/standard_sas.R:9-20`）。

要求 `eq`/`ne` 为单一 atomic scalar，`in`/`not_in` 为非空同类型 atomic vector，并拒绝 YAML mapping/null；为每种 predicate 增加 R apply 与 SAS render 的一致性测试。

## Case promotion records do not enforce promotion or aggregation

**Confirmed, high severity.** `standard_validate_pattern_items()` 只检查 exact keys、少量 forbidden key names 和 nested records，不检查字段类型/值（`R/case_summary.R:13-25`）。Registry status、decision、reviewer/time、evidence IDs、regression status、`independent_study`、`aggregate_only` 都不受约束（`R/case_summary.R:44-58`）；顶层保持 `candidate/not_promoted` 也不妨碍 registry 写 `promoted`、record 写 `approved`，同时只引用一个非独立且回归失败的 evidence。

Subject 保护同样只看 key name，`aggregate_summary: "subject P001 ..."` 这类 scalar 会通过。对 approved/promoted 状态实施 enum/type、`aggregate_only=true`、非空审核人/时间、regression passed、2–3 个 unique study IDs 和状态一致性校验；将 aggregate summary 改为 counts/statuses 的 closed schema，并补充 false aggregate、重复 study、空 reviewer、failed regression 和 subject-like value 的负向测试。

## Safe model identity is checked after a possible overwrite

**Confirmed, medium severity.** Contract 只检查原始 group ID 唯一（`R/standard_contract.R:114-127`），model path 却把所有非 `[A-Za-z0-9_-]` 字符替换为 `_`（`R/standard_engine.R:378-383`）。`A/B` 与 `A?B` 都写 `A_B_mmrm.rds`；第二个 fit 会覆盖第一个。Collector 最终会因 model identity 不符而拒绝，但 standalone wrapper 已可能写出成功 run record 并正常返回。

对 group ID 应复用 analysis ID 的安全 grammar，并在拟合前校验所有安全化 model destinations 唯一。

## Approved adapter generation can leave a mixed generated set

**Confirmed, medium severity.** Generator 在检查 adapter 存在性和 digest 前先写 wrapper/SAS（`scripts/generate_standard_study.R:57-71`）；adapter 缺失时还会在 approved path 创建通用 pass-through 文件。Hash 不符会留下未批准 adapter 和部分新 wrapper/SAS，而 collector 仍是旧版本。

Approved adapter 应作为 immutable input：任何生成写入前验证全部 adapter；scaffold 使用独立的 pre-approval 命令；全部文件先渲染到临时位置，验证通过后再替换，并报告或移除 contract 已删除 analysis 的 stale generated files。

## SAS execution state is not enforced

**Confirmed, medium severity.** 无 adapter/RDS 时 renderer 输出 active DATA step 和 `proc mixed`，仅 ODS CSV 被注释（`R/standard_sas.R:39-43,63-116`）。替换 input placeholder 后提交文件会立即拟合，但 header 仍写 `template_generated_not_executed`；文档承诺的 ODS OUTPUT stub 也不存在，`ods csv` 不是 `ods output`（`SKILL.md:121-129`）。

默认加入 `%abort`/activation macro，只有显式批准 flag 才运行；激活时更新状态，并校验/quote 所有 contract-supplied SAS identifiers，生成与 R estimands 对应的命名 ODS OUTPUT stubs。

## Failure and collector controls lose operational meaning

**Confirmed, medium severity.** Engine 在 approval 前创建 output tree（`R/standard_engine.R:345-348`），之后只按 `phase == "model"` 分类：contract/hash/adapter 错误变成 `blocked_data`，缺少 `callr` 等环境错误变成 Red `fit_failed`（`R/standard_engine.R:352-376,446-457`）。增加 `failure_domain`/phase（approval、contract、adapter、environment、data、fit、inference），并把目录创建推迟到 approval gate 之后。

**Confirmed, medium severity.** 文档称 specification `fail_fast` 可覆盖默认策略（`SKILL.md:113-120`、`references/workflow.md:40-43`），generated collector 却只读取 CLI `--fail-fast`（`R/templates/run_all_mmrm_template.R:44-46`）。Collector 即使所有 analysis 都 blocked/failed，也只写 failed summary 后 invisible return（`R/standard_artifacts.R:302-327`）。定义 spec/CLI precedence，并让 terminal overall failure 在保留 manifest 后返回非零。

## FCN compatibility validation is optional but reported as mandatory

**Confirmed, low severity.** Legacy metadata 同时省略 contract file/hash 仍会通过（`R/tests/check_standard_profile.R:150-156`），当前 FCN V2 wrappers 也实际 source 新 `study_paths.R`。但 root validator 的 FCN block 仅在 fixture 存在时执行（`scripts/validate_project.ps1:177-271`），最终消息无条件宣称 FCN fixture 通过（line 272）。

若兼容性是 release gate，则 fixture 缺失应失败；否则输出 `skipped`，不能计入成功声明。
