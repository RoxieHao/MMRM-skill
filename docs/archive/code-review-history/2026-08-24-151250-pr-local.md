# Intake review strictness and finalization safeguards

The change tightens six-column intake rendering and parser diagnostics, loads `standard_contract.R` in the finalization CLI, and adds CLI self-check coverage. Stale generated-issue cleanup, however, treats every `PLAN-*` ID as machine-owned even though the review schema does not reserve that namespace. A blocked finalization can therefore remove a statistician-authored decision.

Watch for: **confirmed** — blocked finalization can silently delete statistician-authored `PLAN-*` issue rows.

**Verdict**: NEEDS_CHANGES

## High-level view

The renderer now checks the six-column schema before emission, while the strict parser reports interrupted/additional tables with one-line/`<br>` remediation. The CLI sources `standard_contract.R` in normal and self-check paths.

Stale issue cleanup relies only on the `PLAN-` prefix. Section 7 accepts arbitrary `issue_id` values, so generated blockers and statistician-authored issues are indistinguishable.

## Stale blocker cleanup can erase statistician decisions

`review_finalize_render_blocked_section()` now filters `existing` with `!grepl("^PLAN-", issue_id)`. `statistical_review_issues()` validates only the five table columns and does not reserve the prefix, so a valid unresolved row such as `PLAN-ENDPOINT-01` is omitted whenever an independent live validation error causes a blocked review rewrite. This is **confirmed** at `.codex/study-mmrm-analysis/R/review_finalization.R:19-20` and `.codex/study-mmrm-analysis/R/specification.R:51`.

The regression verifies removal of the generated `PLAN-SCHEMA-STUDY-ID` after its cause is fixed, but never seeds a reviewer-authored `PLAN-*` row and checks preservation (`scripts/check_analysis_plan_finalization.R:28-33`). Cleanup needs explicit provenance or a narrowly reserved namespace rejected at parse time.
