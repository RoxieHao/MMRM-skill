# Approved analysis plan execution chain and audit migration

This change replaces endpoint-mapping/specification authorization with a typed analysis plan, canonical approval payload, transactional contract/program publication, and approval-plan-contract runtime identity. Plan/contract parity and source/identity checks are generally fail-closed. The remaining blockers are recovery trust and downstream audit validity, with additional lifecycle and typed-recode gaps. The breaking migration itself is not treated as a defect.

Watch for: **confirmed** transaction journals can name arbitrary filesystem targets; **confirmed** case summaries bypass the collector’s full artifact gate; **confirmed** recode diagnostics are discarded; **confirmed** removed analyses leave stale output trees; **confirmed** finalization failures never reach the review issue table; **likely** SAS character recodes containing macro triggers do not render literally.

**Verdict**: NEEDS_CHANGES

## High-level view

The authorization chain binds review execution content, the normalized plan, registered source evidence, and profile version. Contract compilation copies statistical semantics, while runtime rechecks parity and pinned wrapper identities.

Approval publication stages the review, contract, wrappers, SAS templates, and collector with rollback backups. Recovery accepts paths directly from a YAML journal before validating the study, creating an arbitrary overwrite/delete boundary.

Collector validation covers output schemas, diagnostics, models, and approval identity. Case-summary generation does not reuse it and permits missing diagnostics, so the final aggregate audit artifact can certify an incomplete execution set.

Typed recodes run in the approved adapter→derivation→filter order, but their aggregate policy outcomes remain transient and SAS character literals remain exposed to macro interpolation. Reapproval removes obsolete generated programs but leaves removed analyses’ old execution outputs in the active tree.

<details><summary>Details</summary>

## Transaction recovery trusts journal-controlled filesystem paths

`analysis_approval_recover()` passes `state$entries` from `backup-trace/analysis-approval-transaction.yaml` directly to rollback and cleanup (`.codex/study-mmrm-analysis/R/analysis_approval.R:32-42`). Those functions copy `backup` to `target` and unlink `target`, `stage`, and `backup` without confirming that they belong to the current study’s formal target set. A crafted or corrupted journal therefore causes the next approval command to overwrite or delete any path writable by R before review, plan, source, or approval validation. This is **confirmed**.

Validate a closed journal schema and transaction identifier. Reconstruct allowed targets from formal review/contract/generated paths, canonicalize them with reparse-point checks, and require stage/backup files to be transaction-specific siblings; never execute arbitrary serialized paths.

## Case summary bypasses collector artifact validation

`standard_validate_analysis_artifacts()` verifies exact CSV schemas, output paths, run/diagnostic consistency, model identities and formulas, groups, and approval hashes. `standard_case_summary()` performs only partial run-record checks (`.codex/study-mmrm-analysis/R/case_summary.R:189-217`) and explicitly accepts a missing diagnostic file (`:218-225`). This **confirmed** gap lets a hash-bearing edited run record and manifest produce a case summary while required outputs/models are missing or malformed.

Generate each case-summary entry from the full artifact validator using the active chain and expected analysis. Preserve only its aggregate projection, but require diagnostics and validated output/model artifacts whenever the run status requires them.

## Recode execution evidence is discarded

`standard_apply_derivations()` computes input/output value counts and unmatched/missing policy outcomes, then `standard_prepare_analysis_data()` carries them only in a `derivation_diagnostics` attribute (`.codex/study-mmrm-analysis/R/standard_engine.R:97-119,155-156,254`). No production consumer persists that attribute, and the diagnostic schema has no recode audit field. This is **confirmed**: formal runs cannot demonstrate how approved recode policies affected rows.

Persist controlled aggregate recode diagnostics bound to run ID and approval-plan-contract hashes, then validate them in the collector. Do not retain subject-level values.

## Removed analyses leave stale execution artifacts

Obsolete calculation covers only paths from `analysis_generated_targets()`—wrappers, SAS templates, and the collector (`.codex/study-mmrm-analysis/R/analysis_approval.R:79-82,131-133`). It omits `output/standard-mmrm/<analysis_id>` run records, diagnostics, logs, tables, and model files. This is **confirmed**. Current collectors ignore removed IDs, but humans and glob-based consumers can mistake those active-tree files for current evidence.

Add removed analyses’ complete output roots to the transactional delete set. If retention is required, move them transactionally to an identity-labelled historical archive outside the active output tree.

## Finalization failures do not enter the statistician-facing issue table

`finalize_statistical_review()` constructs stable `PLAN-*` issue rows but returns without publication whenever any exist (`.codex/study-mmrm-analysis/R/review_finalization.R:27-49`). Section 7 is replaced only on success (`:50-56`). This is **confirmed**: schema, trace, hash, identity, and legacy blockers remain outside the primary human review/audit record.

Publish a pending, non-signable review containing generated Section 7 issues while preserving reviewer resolutions and clearing readiness/signature state. Keep invalid plans unable to reach approval.

## SAS recode character values are not macro-safe

`standard_sas_quote()` emits double-quoted literals and only doubles embedded quotes (`.codex/study-mmrm-analysis/R/standard_sas.R:1-5`). Valid approved character values may contain `%` or `&`, which an activated SAS template can macro-resolve instead of matching literally. This is **likely** to change recode, group, or treatment semantics.

Use SAS-safe single-quoted data literals with apostrophe escaping, reject control characters, and add golden cases for apostrophes, quotes, `%`, `&`, blanks, and Unicode. Emit the required blocking template when a normalized value cannot be represented.
