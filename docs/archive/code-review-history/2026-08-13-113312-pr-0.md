# FCN-159-002 V2 条件区域效应与可追溯执行链

本轮把五个 MMRM analysis 放到 workbook 与 execution SHA 约束的 V2 路径，并按当前 ADaM 在 analysis 级决定区域固定效应。R 与 SAS 正常路径均实现 REGION 优先、仅在 REGION 不存在时选择 COUNTRY、少于两个非缺失水平时 omitted 且不使用 SITEID；实际数据因此统一选择 COUNTRY 并省略区域项。重跑结果与 legacy 在四张可比较 TFL 上数值一致，但失败 diagnostics 会被 collector 错误降格，collect-only 对复用产物的内容一致性校验也不足。SAS 尚未执行，当前只能确认模板语义。

**Watch for:** **[confirmed, blocking]** 顶层 data-QC 阻断 diagnostics 缺少 collector 必需的 `region_effect_status`/`region_omission_reason`，会把 `blocked_data` 拒绝并替换成 `blocked_mapping`；**[confirmed, blocking]** collect-only 不核对 CSV 内容或 record status 与 group diagnostics 的聚合结果。

**Verdict**: NEEDS_CHANGES

## High-level view

批准 gate 当前连贯：正式 workbook SHA 与 specification metadata 一致，specification 全文件 SHA 与 R wrappers、SAS templates 和实际 diagnostics 一致，workbook 还单独绑定第 1–8 节 execution SHA。candidate generator 只能生成 pending、空批准值和未解决 issue，且不读取 specification 计算批准 hash。

R 在批准筛选后按整个 analysis 计算区域水平数，included 时才删除区域缺失并把区域项加入公式，omitted 时保留记录并删除公式中的区域项。阻断路径却存在 schema/status 断裂，未执行 group 的风险分类也与规格不符；REGION included 和无 REGION/COUNTRY 分支没有自动化证据。

五个 SAS template 采用相同的 REGION→COUNTRY、动态 CLASS/MODEL 和 omitted 继续逻辑；`%abort` 只保护重复记录或 BASE 不一致。模板未执行，宏展开、ODS 和 R-vs-SAS 数值仍未验证。

Collector 在 run-and-collect 下绑定同一次 invocation，collect-only 则复用 spec SHA 匹配的历史产物。它不重算 status/risk 或验证结果 CSV，因此内部不一致但路径存在的旧产物仍可进入 manifest。

当前五项均记录 `COUNTRY / omitted / fewer_than_2_levels`；三项 complete、一项 fit_failed、一项 partial 与 legacy 状态一致，四项共同 LSMean key 的差异均为零。comparison 没有绑定输入 hash、spec hash 或 invocation，因此只是当前快照证据。

## 阻断产物在 R 与 collector 之间丢失状态语义

**[confirmed, blocking]** `run_fcn_v2_analysis()` 的顶层 error handler 为 input/data-QC 错误设置 `blocked_data`，但最终 diagnostics 没有 `region_effect_status` 和 `region_omission_reason`（`analysis/r/fcn_v2_runtime.R`）。`read_validated_artifacts()` 要求这两列，拒绝后 `empty_record()` 又固定产生 `blocked_mapping`（`analysis/r/run_all_mmrm.R`）。缺变量、重复记录、BASE 不一致或无分析记录因此会失去原始状态和 diagnostic/report 链接；应让 error paths 共用同一 diagnostics 构造器。

**[confirmed, non-blocking]** 受试者或访视不足的 group 写入 `convergence_status=not_assessed`，却写 `computational_risk=Red`。RANGE-OF-MOTION 的 SUMNECK、SUMSHOU、SUMKNEE 已出现该组合，而规格要求“模型未执行，无法评估计算风险”；应改为 Not assessed。

## REGION included 时的 group 可估计性

**[likely, non-blocking]** region decision 在 analysis 级、拟合在 group 级。当 analysis 总体有至少两个区域水平但某个 group 只剩一个水平时，group 阻断只检查记录、受试者和访视；全 analysis 预建的 factor 在 group 子集也没有显式 drop。该 group 可能被 `mmrm` 记为 fit error，或以 dropped-level message 继续，不能稳定满足规格要求的 `blocked_data`。需要拟合前检查 group 的实际 factor levels，并用合成数据确认状态。

**[confirmed, non-blocking]** 可见测试只有共享旧式 approval gate 的 `check_approval_gate.R`。新 workbook execution SHA、REGION 优先、COUNTRY fallback、无候选、included 动态公式、omitted 保留缺失记录、顶层异常 schema 和 collect-only 均无自动化覆盖；production 重跑只覆盖 COUNTRY 单水平 omitted。

## SAS 条件区域项的执行边界

五个 template 都先查 REGION、再查 COUNTRY；只在至少两个非缺失水平时展开 `REGION_EFFECT` 到 CLASS/MODEL 并过滤区域缺失，否则记录 `not_available` 或 `fewer_than_2_levels` 后继续。没有 SITEID fallback，区域 omission 不触发 `%abort`；现有 abort 仅用于重复 key/BASE QC。

**[confirmed, residual limitation]** 模板和报告均标记 `template_generated_not_executed`，AR(1) 也是人工启用段。正式依赖 SAS 前需要在只读 ADAM libname 下执行 omitted 与 included 场景，并验证宏展开、ODS、fallback 和 R-vs-SAS 数值。

## collect-only 缺少内容与聚合一致性检查

**[confirmed, blocking]** `artifact_exists()` 只要求 project-relative path 且 `file.exists()`；`read_validated_artifacts()` 不重算 diagnostics 的 status，不核对 run record 的 status/risk，也不验证 raw/final CSV 可解析且有预期内容。collect-only 又不要求当前 invocation，因此当前 spec SHA 下任意历史组合都可能被接纳。收集时应重算 status/risk，绑定 record 与实际 diagnostic path，并按 QC-OUTPUT-001 验证 CSV。

## 重跑与 legacy 快照的证据边界

当前 specification、wrappers、templates 和 diagnostics 的全文件 SHA 均为 `707CC416FA2DF71826153CFC447D86F5DE2FC3D03861AEC4D9722056ED8E97F7`。region scan 显示 ADQSSUM/ADMK 无 REGION、COUNTRY 各一个水平，而 SITEID 有多个水平；五项 diagnostics 均选择 COUNTRY 并 omitted。PedsQL、疼痛强度、疼痛干扰 complete，肌力 fit_failed，关节活动范围 partial；四项可匹配结果的 LSMean、SE、df、p-value 最大差异均为零，肌力保持 NA。

**[confirmed, non-blocking]** `compare_legacy_v2.R` 不验证 legacy 结果 hash、V2 spec SHA、run ID 或 invocation。当前文件支持本轮结论，但后续任一侧重跑都可能形成混合快照；应在比较前校验并记录两侧 hashes 与 V2 invocation。

## workbook gate 与 candidate 权限边界

正式 workbook SHA `977A5EAB848F1AD2CF9B93BE3F98B9152F06056CBCB048C422583CBDA6FF9FE8` 与 metadata 一致，validation 报告确认其 execution SHA 绑定 specification 第 1–8 节。candidate generator 强制 pending/空批准值、保留 open issues，并断言自身不能 Ready；它只读 legacy inventory，只写 V2 candidate 路径。

**[confirmed, residual limitation]** gate 证明的是文件与 workbook 声明的一致性，而不是 `project_user` 的密码学身份。technical validation 下可接受；正式交付需要外部签名、审计日志或受控权限。
