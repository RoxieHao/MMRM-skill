# Contract-driven Standard MMRM execution and collection

Standard MMRM Profile v1 introduces a versioned YAML contract, approved-specification pinning, linked-source SHA validation, isolated `mmrm` fitting, deterministic R/SAS generation, and contract-driven collection. Thin generated wrappers revalidate specification and contract hashes at execution time, while the collector supports run-and-collect and collect-only modes. The synthetic path exercises a real randomized treatment model and verifies model, table, diagnostic, and run-record outputs. **Watch for:** **confirmed** multi-value equality predicates can silently filter by row position; **confirmed** preparation-stage failure artifacts are rejected by the collector; **confirmed** generated SAS group and QC behavior can diverge from R.

**Verdict**: NEEDS_CHANGES

## High-level view

The contract catalogs analyses, mappings, filters, covariance fallback, estimands, and outputs. Unknown structural keys are rejected, but `eq` and `ne` values are not constrained to scalars, allowing R vector recycling during population selection.

The engine emits stable schemas on errors, but preparation failures use a synthetic `ALL` diagnostic group. Artifact validation requires the exact contract group catalog, so the collector discards those failure artifacts and their root-cause diagnostics.

The SAS renderer carries approval hashes and approved model choices, but uses mutually exclusive group assignment while R evaluates every group independently. Its QC queries also do not gate active `PROC MIXED`, so a filled-in template can analyze a different population or continue after conditions that stop R.

The integration covers one successful analysis and group, treatment estimands, real fitting, collection, and collect-only run-ID stability. It does not cover malformed predicate cardinality, preparation failures, multi-group semantics, or SAS parity.

## Equality predicates can select rows by position

**High — confirmed.** `standard_validate_predicate()` requires a value for `eq` and `ne` but imposes no scalar or atomic constraint (`standard_contract.R:49-55`). `standard_apply_predicate()` evaluates `x == predicate$value` directly (`standard_engine.R:58-62`), so `[A, B]` passes validation and is recycled over rows; a four-row `A` probe returned `TRUE,FALSE,TRUE,FALSE`. SAS takes only the first value, creating a second interpretation. Reject non-scalar `eq`/`ne` values and validate every predicate value as an approved atomic, non-missing type before generation.

## Preparation failures disappear from aggregate diagnostics

**High — confirmed.** The engine represents approval, source, mapping, and preparation errors with `analysis_group_id = "ALL"` (`standard_engine.R:430-434`), while the collector requires diagnostic group IDs to equal the approved group catalog (`standard_artifacts.R:79-80`). A linked-source or preparation failure therefore writes failure artifacts, but run-and-collect rejects them, substitutes a pathless `blocked_data` manifest row, and drops the original diagnostic from aggregation. Accept a defined analysis-level sentinel during failure validation or emit one failure row per approved group, preserving paths and root-cause text.

## Generated SAS does not preserve R group and QC semantics

**Medium — confirmed.** R filters independently for every group, so overlapping rows are copied to each match and unmatched rows are omitted (`standard_engine.R:108-127`). SAS emits `if ... else if ...` and does not delete a missing `_analysis_group` (`standard_sas.R:71-86`), making overlaps first-match-only and retaining unmatched records as a missing BY group. Its duplicate and baseline queries proceed directly to active `PROC MIXED` (`standard_sas.R:88-107`) instead of enforcing R's stop conditions. Expand groups non-exclusively, delete unmatched rows, and abort before modeling when approved QC fails.

## Happy-path integration leaves the blocking branches untested

**Low — confirmed.** `check_standard_profile.R` has one group (`check_standard_profile.R:67-70`) and checks an unknown top-level key, but not predicate cardinality, preparation-failure collection, multi-group behavior, or SAS gating. Child commands may return nonzero (`check_standard_profile.R:155-163`), so later artifact assertions establish the collector success path but not the standalone wrapper exit contract. Add focused contract and failure-collection tests plus multi-group renderer assertions.

All 18 R files in the permitted tree plus the generator parsed successfully. Delegated evidence reports the synthetic integration completed a real `mmrm` fit and cleaned its temporary study; a fresh review invocation exited 1 without diagnostic output, so it did not establish an additional runtime result.
